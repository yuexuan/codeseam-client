## 1. 定稿视觉原则

1. **整窗材质一致。** 背景是低对比度的中性暖白、奶油色、香槟色、淡桃色轻柔渐变，微弱氛围光，不是纸张底色，也不是 macOS 冷蓝紫主题。可借鉴 Windows 11 Mica / Acrylic 的材质处理，但无需机械复制系统控件。
2. **适度玻璃感，不牺牲辨识度。** 内容面板采用半透明白、细白高光与轻暖灰外轮廓、极浅短投影，形成看得见但不割裂的边界。避免高透明导致轮廓融入背景，也不添加整块不透明白色填充。
3. **背景安静，操作突出。** 不用穿透卡片的斜向强光束、明显几何纹、亮橙色大面积渐变。铜金主要给品牌、选中步骤、局部图标和主操作按钮。
4. **信息比装饰重要。** 首屏清晰显示状态结论、分组数据、下一步，减少无意义的标语、双重框线、嵌套背景、状态药丸、深投影和花哨动效。
5. **状态靠图标和文字。** **检测结果每一行右侧不使用彩色药丸背景**：绿色勾 +「已检测」、橙色警示 +「待处理／待检测」、灰色问号 +「无法确认／可选」。注意状态文案必须遵循真实语义；不可把「已安装」等同「已验证」。
6. **汇总结果可有限强调。** 顶部「3 项待处理」这类汇总提示允许非常浅的暖橙背景，且仅限摘要，不应复制到每条状态。绿色汇总可直接使用图标和文字。
7. **视觉架构不等于业务架构。** 状态在卡片内，详细诊断按需展开；不要因新模块增加而无限堆卡片，亦不可牺牲信息完整性。

## 2. 品牌与窗口

- **唯一应用 Logo：** `src/codeseam/assets/codeseam-logo.svg`，即已有的**铜金色开口 C 圆环 + 右上金色圆点**。禁止替换成火焰、盾牌或其他新图标。
- **左上角：** 仅放此 Logo icon，**不显示 CodeSeam 字样**。
- **右上角：** Windows 最小化、最大化/还原、关闭控件。与其他内容保持适当间距；窗口控制键可独立命中。
- **导航：** 初始化向导采用顶部水平步骤条（约 6 个归并阶段）并突出当前序号；**不设常驻左侧导航**。已初始化工作台同样不设常驻侧边栏，详情从卡片进入、顶部返回。
- **字体：** Segoe UI / Microsoft YaHei / 系统无衬线；主标题粗、分组标题半粗、内容中等、说明弱化；不要依赖浅色小字承载重要状态。
- **行距与密度：** 面向 Windows 桌面应用，不作过度稀疏的仪表盘。表格式三列信息靠近、间隔稳定，左右各区的状态列右对齐。

## 3. 视觉令牌建议（落地时以真实截图校准）

以下为**目标令牌与推荐初值**，不是声称现有 CSS 已生效。应用端当前令牌在 `src/codeseam/styles/tokens.css`，迁移时保持单一来源。

| 元素 | 推荐初值 / 用法 |
| --- | --- |
| 背景基础 | `#F4F2F0` 中性暖白；周围微弱奶油、香槟、粉桃多层渐变，整体色差控制低 |
| 背景氛围 | 低饱和 `radial-gradient`，局部叠色约 5–10%，**不加明显光带** |
| 玻璃面板 | `rgba(255,255,255,0.55–0.65)`，允许随系统能力回退到半透明材质 |
| 玻璃模糊 | `backdrop-filter: blur(18px–24px)`；必要时在不可用平台降级 |
| 轮廓 | 细白内高光 + 浅暖灰外边界；不能仅靠纯白描边区分 |
| 阴影 | 中性暖灰黑约 4–6% 低透明度，柔和扩散，切忌重阴影 |
| 文字 | 主文 `#22252B`，次文 `#5F636D`，低优先级文本 `#8B8E97` |
| 铜金 | `#B87324`，强强调 `#9C5E14`；主按钮可用品牌金渐变 |
| 正常 | 绿色 `#37A06C` 图标 + 文字，行状态**无填充** |
| 待处理 | 橙金 `#C08A20` 图标 + 文字，行状态**无填充** |
| 异常/错误 | 红色 `#C0524A`，按语义使用；向导不设额外退出按钮 |
| 未知/可选 | 灰色图标 + 文字，行状态**无填充** |
| 圆角 | 按控件/组件层级采用 8 / 12 / 16px；保持同系列 |
| 分隔 | 列表使用极轻细线，不给每条结果增加卡片边框 |

**色彩约束：** 用可观察的状态和层次验证可读性；不要盲目套用透明度数值。玻璃与主背景相邻时需有足够的边缘明暗差；文本和控件焦点的可访问性对比度优先于材质效果。高对比度模式、低 GPU 配置和禁用透明效果时应提供不损失信息的降级显示。

## 4. 首次初始化 · 环境预检页（当前唯一已确认页面参考）

**整体骨架：**

```text
┌──────────────────────────────────────────────────────────┐
│ [CodeSeam C icon]                         [－][□][×]   │
│          [1 环境预检] ── [2 节点与代理] ── ...         │
│ 环境预检                                       [刷新]   │
│ 检查这台电脑是否已准备好运行 Claude 全家桶                │
│ ┌─────────────────检查结果摘要───────────────────────┐ │
│ │ ● 基础检查已完成 / 待处理项 / 初步检查状态           │ │
│ └──────────────────────────────────────────────────┘ │
│ ┌──────────基础系统─────────┐ ┌──────Claude 全家桶──┐│
│ │ 图标 名称     观测值   状态 │ │ 图标 名称   值  状态 ││
│ │ ...                      │ │ ...                 ││
│ └──────────────────────────┘ └─────────────────────┘│
│ ┌──────────网络与代理───────┐ ┌──────可选运行能力───┐│
│ │ 图标 名称     观测值   状态 │ │ Hyper-V ...    可选 ││
│ │ ...                      │ │                     ││
│ └──────────────────────────┘ └─────────────────────┘│
│ (i) 修改前会预览并备份                                  │
│                                         [下一步 →] │
└──────────────────────────────────────────────────────────┘
```

- **四模块严格 2×2 对称**：上左「基础系统」、上右「Claude 全家桶」、下左「网络与代理」、下右「可选运行能力」；相邻列统一间距，两列各约半幅宽。**不用改成一列、长表格或多个不对齐的分组。**
- **四块面板轮廓统一**，内层不再叠加大块区分背景；右下角即使行数少，也不增加虚假检测项来填充空间。
- 上方一条横向摘要面板，突出主结论；下方一条低调、可读的变更/备份说明；底部固定操作区。
- **不再设置独立退出按钮：** 退出统一使用 Windows 窗口右上角关闭控件；向导步骤状态按需保存，下次打开可以安全续接。第一页底部只保留右侧主按钮，后续页面左侧放「上一步」。
- **右下主按钮：** 仅「下一步」+ 右箭头，铜金渐变；**不出现「下一步：配置节点」**等长文案。操作前的修改预览、备份说明在内容区完成。
- **重新检测：** 标题右侧独立刷新 icon，不增加冗长标签；保留 tooltip / 辅助说明。
- 行内观测列自然对齐，状态列靠右；结果语义区分「已检测 / 已安装 / 待处理 / 待检测 / 无法确认 / 可选」等，前后文一致。
- 顶部的完整初始化可以包含条件步骤，**六个高层阶段仅是视觉归并**；详细编排与验收以 [01 初始化向导](../../../docs/产品/01-初始化向导与依赖编排.md) 为准。
- 图中 Windows 11、时区、节点和应用状态仅为**示例演示值**，不得作为运行时事实或项目已验收结论。

## 5. 其他页面继承规则

- **工作台：** 无常驻边栏，概览结论最突出；账号与 Runtime、网络、浏览器、Claude 全家桶、事件记录按优先级展开。允许针对业务重组版式，但必须保持同样的暖白玻璃材质、清晰轮廓、铜金强调和无底色行状态。
- **节点与代理：** 第二步只帮助用户导入自己的节点并选择当前网络出口。左侧为多节点 / 单节点链接导入与节点列表；导入成功后列表自然成为主体，添加入口保留但收敛。右侧为「当前选择的出口」，展示节点名称、可理解的地区、基础延迟与快速测试状态。**不展示 Mihomo 核心面板或代理协议教学**；Mihomo 只是内部实现。无 YAML、二维码、手动协议字段表单，不做自动最优节点选择。底部只留「上一步」和「下一步」，无退出按钮。
  - **完整交互规格：** [02 节点与代理管理 · §10](../../../docs/产品/02-节点与代理管理.md#10-初始化第二页--用户操作与页面状态2026-11-11)，覆盖多 / 单节点导入、选择当前出口、快速测试、错误反馈和后续出口继承。该系列为交互设计目标，不代表功能现已落地。
- **Claude 配置清理（第三步）：** 页面核心是发现的旧配置、作用范围、备份状态和清理复验；不放 Claude 安装按钮，不展示三个应用的安装卡片。采用左侧配置清理清单、右侧扫描摘要/备份保护信息的双栏结构；每项先预览，备份成功且用户确认后才清理。无已安装 Claude 产品时允许跳过。普通状态只用图标和文字，不使用填充药丸。
- **Claude 应用入口（第六步）：** 已安装的 Code / Desktop 提供受管「启动」入口；未安装的应用提供「打开官方安装页」，由 CodeSeam 专用浏览器打开、用户自行安装；Web 提供「打开 Claude Web」。安装与启动结果未验证前不得显示为已就绪。
- **Runtime / Hyper-V：** 长流程采用局部步骤导航或可展开详情，不堆叠多层表面卡片。第四步「运行环境」沿用顶部六阶段步骤条，顶部增加已选出口摘要条；主体采用左右两栏，左侧为系统环境检查列表，右侧为时区处理与 Native / Virtual 选择。语言偏好独立于时区；Virtual 的 Hyper-V 兼容性检查、安装 / 重启、VM 创建和 Guest 初始化作为条件子流程，不增加顶层步骤。
- **异常事件：** 异常信息必须清晰可见，必要时可在单一关键警告区域使用低饱和红/橙背景，但**普通列表状态仍不使用底色药丸**。
- **设置与诊断：** 强调检索与决策效率；不要继承旧版设置页的常驻侧边栏、旧业务用量页面和旧主题色分区作为现行 UI。

## 6. 新增页面验收清单

- [ ] 官方开口 C 标识无误；标题栏只有 Logo icon，不显示产品名。
- [ ] 背景是克制的中性暖白香槟玻璃，无明显暖色强光斜带和 macOS 蓝紫底。
- [ ] 组件边界完整、可辨，背景不过分抢眼；四角、阴影、内高光和间距一致。
- [ ] 结果行右侧**只有图标和文字，没有绿/橙/灰状态底块**。
- [ ] 主按钮仅一个显著铜金操作，文案简洁；**无独立退出电源按钮**，通过系统标题栏关闭；第二步及以后保留「上一步」。
- [ ] 无常驻侧边栏；步骤导航与详细入口符合当前产品架构。
- [ ] 检测状态和演示数据不误导：未测/未覆盖/无法确认不能当成通过。
- [ ] 桌面常见窗口尺寸下不会有超宽列距、字段脱位、卡片轮廓消失、溢出和遮挡。
- [ ] 降低透明效果、深色模式、键盘焦点和高对比度时仍保持可读。

## 7. 实现与旧版边界

- 现有 CSS：`src/codeseam/styles/tokens.css` 是**待迁移的实现**，旧变量值仍可能是纸感白卡。**不要把旧值视为当前设计规范**；后续实现应统一在该文件扩展/替换新材质 token，避免散落硬编码。
- 旧版设计说明：[DESIGN-LEGACY-2026-11-04.md](DESIGN-LEGACY-2026-11-04.md) 与本目录 2026-10 / 11-04 截图是**历史实现证据**，不应用于推导新页面视觉。
- 产品设计顺序：先按本文件出每个页面高保真稿，用户确认后才逐页更新对应代码；**此处只固化设计，不修改应用 UI 运行实现**。
